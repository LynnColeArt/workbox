# Hubnot native collaboration contract

The Workbox deployment binary at `graph-QQIhU2/hn` reports `0.0.1-dev`. The inspected Hubnot source was local `main` at `91f3e09d`. The Workbox contract fixtures invoke the configured binary directly against isolated Git repositories. A version string alone cannot establish feature availability.

| Surface | Read and write behavior |
| --- | --- |
| Issue reads | `issue list --details` returns current state, opening metadata and immutable root IDs. `issue show` returns state, head IDs, revision and comment counts, and conflict state. `heads` returns attributed full head states. Use `history --kind comments` for comment IDs, actors, timestamps, and Markdown source. Issue pagination uses envelope-level `snapshot` and `next_cursor`. |
| Issue writes | `open`, `comment`, `revise`, `close`, `reopen` and `resolve` use full event IDs where applicable. Use `--input -` for full-state open, revise, and resolve. Merge an edit into the observed state to preserve criteria, relations, assignees and metadata. Ordinary edits pin one current head. Resolve pins all competing heads. Successful results have `data.issue_id` and `data.event_id`. |
| Discussion reads | `discussion list`, `show`, `heads`, `history`, and `replies` return verified visible resources. List and reply pages use `data.snapshot` and `data.next_cursor`. Thread detail provides `reply_count` and an optional exact `accepted_answer`. Conflicted resources have null state and explicit heads. |
| Discussion writes | `discussion open/revise/close/reopen/category/answer`, `discussion reply add/edit`, and full-state `discussion resolve` and `discussion-reply resolve` cover the required write flows. Contextual replies use the parent reply root. Accepted answers use the exact reply revision. Later reply edits preserve that accepted content. Successful results have `data.resource_id` and `data.event_id`. |
| Identity and policy | `identity show --json` identifies the active signer. `--actor` pins it and rejects a mismatched fingerprint. The tested collaboration CLI does not provide a per-action dry-run or actor-switch operation. Contribution authorization is enforced at write time when the repository has selected an authority with contribution policy. Repositories without that policy can accept edits by different signing actors. The adapter should surface known unavailability and pass native denials through both transports. |
| Retry | `--operation` binds an intentional mutation to its signer and semantics. Exact replay returns the original signed event and a changed request is rejected. Lookup is `issue operation`, `discussion operation`, or `discussion-reply operation` with explicit actor and operation key. Keep payload and expected revision through retries. Native responses may include admission state. A signed result and its Workbox index refresh have independent outcomes. |
| Native capability gaps | Native issue comments are append-only. There is no issue comment editing or deletion command in either examined surface. The specification makes those operations capability-dependent. Browser and MCP should keep those capabilities unavailable pending an explicit Hubnot extension. Discussion replies have a native edit operation. |

## Verification

- Workbox `tests/collaboration-native.test.ts` verifies read compatibility for an old-format Ed25519-signed issue, exact Markdown and full-state label changes, issue operation lookup and replay without a second write, actor mismatch, stale rejection, and a signed sibling conflict transferred between repositories and resolved using all current heads.
- The same suite verifies contextual discussion replies, native cursor placement, replay and reply operation lookup, pinned accepted answer content after editing the reply, stale mutation denial, and clearing the answer.
- Hubnot source tests passed from a disposable archive, including `TestIssueCommandsReplayLifecycle`, `TestIssueCommandsConflictAndPartialResolution`, `TestDiscussionNativeLifecyclePinnedAnswerAndReads`, and `TestContributionCLIGovernedSpecializedResourcesAndHiddenDependencies`. The last test confirms that governed visibility controls reads and that operation recovery can retain the exact signed identity while redacting hidden content.
