# Acceptance quickstart — Workbox addresses and deep links

Use a disposable Workbox checkout and index with a Firewalker fixture, a numbered issue, and known memory and pipeline records. Start the implementation under test on a non-default loopback port. Do not use the demo repo as a write fixture.

1. **Web entry** — From the keyboard, open **Open address**, paste `workbox://home`, and verify the Dashboard opens. Repeat with Firewalker’s canonical address, its legacy alias, and its numbered issue. Submit a missing project, an invalid address, and Trending. Verify the page retains the input and explains the error. If Explore has shipped, verify `workbox://projects/` opens it. Otherwise verify the unavailable message.
2. **MCP** — Start the stdio server against the same fixture. Confirm `resources/list` emits canonical addresses. Use `resources/read` on the canonical and legacy project, issue, memory, and pipelines addresses and compare their parsed `text` payloads. Check both top-level resources, rejected addresses, and redaction of injected full IDs in fixture content. Confirm the project payload has no local path.
3. **Desktop** — On each target OS, install the release-candidate handler through its documented opt-in flow. Configure the test origin and make the test browser the default. Click an ordinary page link to `workbox://projects/firewalker/` and follow the [DL-001–DL-003 matrix](spec.md#browser-deep-link-acceptance-matrix). Verify the destination matches in-app paste and record browser, OS, build, configured port, and result.
4. **Recovery** — Cancel the launch confirmation when shown. Stop Workbox and repeat the click to verify the handler reports how to start or reconfigure it. Verify a mismatched probe cannot trigger a browser launch. Disable or uninstall the handler and verify paste still works.
5. **Release evidence** — Run the web and stdio regression suite plus type checking and the production build. Record Windows/Edge evidence against the upcoming Windows release candidate. Verify a platform before documenting its support.
